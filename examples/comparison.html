Comparing Binary Search Tree Search Strategies

An interactive visual deep-dive into 3-Way, Sentinel, and 2-Way BST search algorithms.

In textbook Binary Search Trees, search algorithms look simple on paper. However, in production runtimes, branch mispredictions and redundant leaf/null checks create significant microarchitectural overhead. Below, we explore three distinct search techniques applied to the exact same tree values (level-order array: [8, 4, 12, 2, 6, 10, 14, 1, 3, 5, 7, 9, 11, 13, 15]), searching for key 6.

1. Default (3-Way) Search
Conventional BST search. At each node, the search checks for less-than (<), equal-to (===), or greater-than (>). It explicitly verifies null at each leaf before terminating.
2. Sentinel Search
Sentinel nodes are inserted at every leaf position. At the start of the search, all sentinel nodes are assigned the target value. The main traversal loop performs zero null checks, guaranteeing that a matching node will always be found. Upon match, a single check confirms whether the matched node is an authentic tree node or a sentinel leaf.
3. Two-Way (Candidate-Based) Search
Eliminates the three-way branch by executing only a single less-than (<) comparison at each node during tree descent. Whenever target >= node.val, it records the node as a Candidate and branches right. Equality is deferred until a leaf is reached, requiring only one equality test for the entire search.
